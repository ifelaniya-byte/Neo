## 🔬 System Architecture: The Dual Karpathy Loop

### Loop 1: Code Task Optimization (`worker_core.py`)
* **Generate:** Micro-model (or Gemini) creates performance patches
* **Evaluate:** `eval_harness.py` measures execution time and accuracy
* **Ratchet:** Git commits wins, discards losses
* **Export:** Winning strategies saved to `verified_trajectories.jsonl`

### Loop 2: Micro-LLM Architecture Evolution (`train_micro_core.py`)
* **Self-Refinement:** Model optimizes its own training code
* **Compression:** Quantization (FP16→INT8→NF4) and layer pruning
* **Distillation:** DPO alignment on winning vs. losing strategies
* **Validation:** New checkpoints tested before committing

## 📊 Evaluation Metrics ($S_{\text{eval}}$)

The composite score balances multiple optimization objectives:

$$S_{\text{eval}} = 0.4 \times S_{\text{loss}} + 0.3 \times S_{\text{speed}} + 0.2 \times S_{\text{ram}} + 0.1 \times S_{\text{tests}}$$

* **Loss Score:** Mathematical accuracy of computation
* **Speed Score:** Execution time relative to baseline
* **RAM Score:** Memory efficiency and headroom
* **Test Score:** Unit test validation

### Git Configuration Issues
If Git commits fail, ensure:
```bash

git config --global user.email "your.email@example.com"
```

### API Rate Limiting
If Gemini API errors occur:
* The system will automatically retry with exponential backoff
* Consider switching to local LLM for uninterrupted operation

### Memory Constraints
If `eval_harness.py` reports high memory usage:
* The agent will automatically optimize for memory efficiency
* Consider reducing iteration count in `worker_core.py`
